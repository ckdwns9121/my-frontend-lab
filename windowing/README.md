# 순수 JavaScript 가상 스크롤 실험

전체 데이터를 DOM으로 만들지 않고, 현재 화면에 필요한 행만 렌더링하는 Windowing을 직접 구현한 예제입니다.

## 실행 방법

저장소 루트에서 정적 서버를 실행합니다.

```sh
python3 -m http.server 5173 --bind 127.0.0.1
```

접속 주소: http://localhost:5173/windowing/

## 실험 조건

- 데이터: 테스트용 주문 1,000건
- 행 높이: 패딩과 테두리를 포함해 50px 고정
- viewport 높이: 200px
- overscan: 화면 위아래 두 행씩
- `end`는 포함하지 않는 경계

## 구현한 내용

1. `scrollTop`과 `clientHeight`로 화면에 걸치는 시작·끝 인덱스를 계산합니다.
2. 보이는 범위의 앞뒤에 `OVER_SCAN = 2`를 더해 렌더링 범위를 넓힙니다.
3. 넓어진 범위로 `top-spacer`, `bottom-spacer`, 실제 행을 함께 갱신합니다.
4. `Map`에 현재 행 DOM을 보관하고, 다음 범위와 겹치는 행은 재사용합니다.
5. 범위 밖으로 나간 행은 DOM과 `Map`에서 함께 제거합니다.
6. `cursor`로 삽입 위치를 맞춰 위아래 스크롤 모두 행 순서를 유지합니다.

`index.js`는 연습하며 작성한 구현을 그대로 옮겼습니다. 아래쪽 빈 공간의 빨간 표시는 디버깅용입니다. 높이 계산에 영향을 주지 않도록 CSS `outline`으로 표시합니다.

## Overscan이 필요한 이유

화면과 겹치는 행만 만들면, 빠르게 스크롤할 때 새로 보일 행을 계산하고 DOM에 추가하는 작업이 필요합니다. 이 작업이 화면 이동을 따라가지 못하면 빈 구간이나 깜박임이 나타날 수 있습니다.

이미 가져온 데이터의 앞뒤 행을 조금 미리 DOM으로 만들어두면 작은 스크롤 이동에 대비할 수 있습니다. 이 예제는 앞뒤 두 행을 준비합니다. 원격 데이터를 추가로 가져오는 기능은 아닙니다.

```js
const OVER_SCAN = 2;
const renderStart = Math.max(0, start - OVER_SCAN);
const renderEnd = Math.min(data.length, end + OVER_SCAN);

updateTopSpacer(renderStart);
updateBottomSpacer(renderEnd);
updateRows(renderStart, renderEnd);
```

`start`, `end`는 화면에 보이는 범위이고, `renderStart`, `renderEnd`는 실제 DOM을 만드는 범위입니다. 처음과 끝에서 데이터 범위를 벗어나지 않도록 제한합니다. 실제 행이 늘어난 만큼 빈 공간도 줄어야 하므로 세 함수에 같은 렌더링 범위를 전달합니다.

## 계산 예시

| scrollTop | 보이는 인덱스 | 렌더링 인덱스 | 행 DOM 개수 |
| ---: | --- | --- | ---: |
| 0px | 0~3 | 0~5 | 6 |
| 50px | 1~4 | 0~6 | 7 |
| 200px | 4~7 | 2~9 | 8 |
| 225px | 4~8 | 2~10 | 9 |
| 49,800px | 996~999 | 994~999 | 6 |

225px에서는 첫 행과 마지막 행이 일부씩 보이므로 보이는 행만 5개입니다. 여기에 앞뒤 2개씩을 더해 DOM에는 9개를 만듭니다.

overscan을 늘리면 DOM과 셀 처리 비용도 늘어납니다. 큰 값이 항상 더 좋은 것은 아닙니다.

## DOM 재사용 확인

인덱스 `0~3`에서 `1~4`로 이동할 때:

- 기존 전체 삭제 방식: 네 행을 제거하고 네 행을 새로 생성합니다.
- 현재 방식: 0번만 제거하고 4번만 새로 만듭니다. 1~3번 DOM은 유지합니다.

개발자 도구 Elements에서 행 하나를 선택한 뒤 스크롤해보면, 겹치는 행이 유지되는지 확인할 수 있습니다. 콘솔에는 계산한 `start`, `end`가 출력됩니다.

위아래 빈 공간과 실제 행 높이의 합은 `1,000 × 50 = 50,000px`입니다. 마지막까지 스크롤하면 `주문 1000`이 보여야 합니다.

## 현재 범위와 다음 실험

고정 데이터·고정 행 높이를 대상으로 한 기본 버전입니다. 범위가 같을 때 갱신 함수 호출을 생략하는 처리, ResizeObserver, 정렬·데이터 삽입·가변 높이는 아직 추가하지 않았습니다.

현재 `Map`은 인덱스를 키로 사용합니다. 데이터의 순서가 바뀌는 기능을 추가한다면 고유 ID와 화면 순서를 구분해 관리해야 합니다.
