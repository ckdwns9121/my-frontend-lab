# 순수 JavaScript 가상 스크롤 실험

전체 데이터를 DOM으로 만들지 않고, 현재 화면에 필요한 행만 렌더링하는 Windowing을 직접 구현한 예제입니다.

## 실행 방법

저장소 루트에서 정적 서버를 실행합니다.

```sh
python3 -m http.server 5173 --bind 127.0.0.1
```

접속 주소: http://localhost:5173/windowing/

## 실험 조건

- 데이터: 테스트용 주문 1,000건
- 행 높이: 패딩과 테두리를 포함해 50px 고정
- viewport 높이: 200px
- `end`는 포함하지 않는 경계

## 구현한 내용

1. `scrollTop`과 `clientHeight`로 화면에 걸치는 시작·끝 인덱스를 계산합니다.
2. `top-spacer`와 `bottom-spacer`의 높이로 생략한 행의 공간을 유지합니다.
3. `Map`에 현재 행 DOM을 보관하고, 다음 범위와 겹치는 행은 재사용합니다.
4. 범위 밖으로 나간 행은 DOM과 `Map`에서 함께 제거합니다.
5. `cursor`로 삽입 위치를 맞춰 위아래 스크롤 모두 행 순서를 유지합니다.

`index.js`는 연습하며 작성한 구현을 그대로 옮겼습니다. 아래쪽 빈 공간의 빨간 표시는 디버깅용입니다. 높이 계산에 영향을 주지 않도록 CSS `outline`으로 표시합니다.

## 계산 예시

| scrollTop | start | end | 표시하는 인덱스 | 행 DOM 개수 |
| ---: | ---: | ---: | --- | ---: |
| 0px | 0 | 4 | 0~3 | 4 |
| 50px | 1 | 5 | 1~4 | 4 |
| 200px | 4 | 8 | 4~7 | 4 |
| 225px | 4 | 9 | 4~8 | 5 |

225px에서는 첫 행과 마지막 행이 일부씩 보이므로 5개 행이 필요합니다.

## DOM 재사용 확인

인덱스 `0~3`에서 `1~4`로 이동할 때:

- 기존 전체 삭제 방식: 네 행을 제거하고 네 행을 새로 생성합니다.
- 현재 방식: 0번만 제거하고 4번만 새로 만듭니다. 1~3번 DOM은 유지합니다.

개발자 도구 Elements에서 행 하나를 선택한 뒤 스크롤해보면, 겹치는 행이 유지되는지 확인할 수 있습니다. 콘솔에는 계산한 `start`, `end`가 출력됩니다.

위아래 빈 공간과 실제 행 높이의 합은 `1,000 × 50 = 50,000px`입니다. 마지막까지 스크롤하면 `주문 1000`이 보여야 합니다.

## 현재 범위와 다음 실험

고정 데이터·고정 행 높이를 대상으로 한 기본 버전입니다. 화면 밖 행을 미리 만드는 overscan, 범위가 같을 때 갱신 함수 호출을 생략하는 처리, ResizeObserver, 정렬·데이터 삽입·가변 높이는 아직 추가하지 않았습니다.

현재 `Map`은 인덱스를 키로 사용합니다. 데이터의 순서가 바뀌는 기능을 추가한다면 고유 ID와 화면 순서를 구분해 관리해야 합니다.
